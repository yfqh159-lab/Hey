# Hey 精简客户端实施记录

> 开发分支：`codex/p0-vpn-mainline`；基线：`65bdea3`。本文件记录已落到源码的变更，
> 不把静态检查等同于真机验收。真机结果只填写在
> [`device-acceptance.md`](device-acceptance.md)。

## 已落地变更

### 代理与 VPN 主链

- `dcfb355`、`050a0d9`、`d97735f`、`fe7fbbe`：真实心跳、失败清理、扩展内异常清理与跨进程状态校正。
- `7c7b678`、`ef6bf64`：默认 DNS 经代理，并在可用系统版本上保护核心进程网络，降低 DNS 泄漏与自身 TUN 回环风险。
- `7f2fe6b`、`335184e`、`fccf1da`：停止闩锁及事务化 VPN 状态文件；崩溃恢复优先采用已完整关闭且结构有效的新临时状态，避免迟到启动或旧 `active` 备份造成误报。
- `89e7565`：VPN 状态临时文件在原子替换前执行 `fsync`；进程中断留下完整新状态时优先于旧主文件，半写临时文件仍安全回退，补充纯函数回归用例。
- `97c1602`、`995d940`、`47a3a33`：本地代理状态独立处理；启动前等待实际 SOCKS 入口，运行中连续探测数据面，失败清理但不自动重连。
- `cc9ec16`、`36c7d85`、`5d112c5`：TUN 与本地 SOCKS/HTTP 成为明确的可选模式；首页显示当前模式，VPN 网络自动化不再影响本地代理。
- `b678e2b`：本地代理模式固定使用主 Xray 内核承载普通 VLESS/VMess/Trojan/Shadowsocks 节点；即使旧设置保留 sing-box 预览选择也不会误入仅支持 VPN 的启动分支。该模式隐藏无效的预览内核选项，sing-box 独有协议直接返回模式不支持错误，不再先展示无法兑现的临时切核确认；源码门禁固定此边界。
- `5322c9b`：解除 Hev TUN 引擎与用户可见本地 SOCKS/HTTP 的遗留强制联动；TUN 数据面只使用固定内部入口，本地代理监听继续由独立开关决定。
- `c7b527e`：清理“原生 TUN 入站”的旧说明，关于页明确展示可选的 TUN 与本地代理模式。
- `9d5505f`、`dc1f8a0`：观察底层 Wi-Fi/蜂窝变化但不强制重建系统 VPN；初版让新连接跟随系统默认承载。
- `b57dcf1`：参考 v2rayNG 的承载切换处理，在真实网络签名变化后仅重载当前 Xray/sing-box 核心，保留系统 VPN 与独立 tun2socks 数据面；短暂无网络时等待下一可用承载，可信网络自动断开和用户停止优先。核心恢复失败会清理整个会话且不自动重连。原生桥同时区分旧版核心自带 TUN 与当前独立数据面，核心停止不再把仍运行的 tun2socks 误报为停止；源码校验固定该边界。
- `91bf344`：补齐本地代理模式的承载切换恢复：真实签名变化时先从未预解析的当前运行配置重新解析节点域名，再原地重载 Xray、等待 SOCKS 入口并复测出口；首次/强制补判与短暂无网络不触发重载。恢复代际由新启动、用户停止和状态校正撤销，任何异步阶段的手动断开都不会被迟到任务重新拉起；失败停止核心、进入错误态并等待手动重连。历史完整配置没有标准健康端口时保持兼容，但仍要求原生核心报告运行。
- `23ffe72`：底层承载识别不再单凭 `wifiManager.isConnected()` 优先 Wi-Fi。空闲/本地代理先采用 NetworkKit 的默认活动网络；TUN 可能成为默认网络时跳过 VPN，并在全部物理候选中优先选择系统已验证可联网的承载，同类多句柄固定最小 ID。这样 Wi-Fi 仍关联但已断网、系统回落蜂窝时不会把核心重载到错误承载；缺少 `VALIDATED` 标记的设备仍保留原有保守回退，纯选择逻辑已覆盖 LocalUnit 用例。
- `0daf189`：网络场景评估与真实承载切换使用不同签名。SSID 因定位权限或系统读取抖动改变可见性时仍重新判断可信网络，但只要同一 NetHandle 未变就不重载核心；NetHandle 真正变化时即使同名 Wi-Fi 也能恢复一次。拿不到句柄时才用 SSID 作为保守回退，避免反复假重载与漏掉可信 Wi-Fi 自动断开之间的冲突。
- `bb7c953`：Xray TUN 首次启动仍可使用当前承载的节点域名预解析结果，但在结果确有差异时同时向 VPN Extension 传递一份保留原始域名和用户静态 hosts 的仅内存重载配置；承载切换不再用旧网络的临时 DNS 映射重启核心。相同配置不会重复进入 Want，降低完整配置的跨进程体积；会话清理后立即释放两份内存配置，不新增敏感落盘或日志。
- `c1fddb6`：连接启动增加独立取消代际，并在核心选择、策略组展开、域名解析、Proxy-only SOCKS 就绪、系统 VPN 授权和 Extension 启动确认等异步边界后复核。用户停止或后台状态校正会先撤销旧代际，迟到启动不能继续创建核心/VPN或覆盖停止结果；Xray、sing-box 与本地代理三条路径使用同一规则。
- `36a9617`：把底层已有的安全启动取消能力接到首页单一连接按钮：`STARTING` 时显示停止动作并允许用户取消，`STOPPING`、热切换和网络恢复仍拒绝重叠操作。经用户确认的控制卡/深链 stop 或 toggle 同样可取消启动，busy 状态下的 start 继续拒绝；纯策略补充 LocalUnit 用例，源码门禁固定页面接线。
- `98fe895`：连接控制器在首个异步启动步骤前固定本次用户选择的 TUN/本地代理模式；用户早期取消本地代理启动时会停止 Xray 本地入口，不再沿用旧/default TUN 模式而无端创建或停止 VPN Extension。源码门禁检查模式赋值必须早于核心选择的第一个 `await`。
- `49c5c1a`：运行时控制器增加页面层启动代际；启动中取消或取消后立即再次连接时，旧 `start()` 续体不能覆盖停止/新会话状态、用旧节点安排测速和出口检测，或迟到清除网络场景停止标志。只有真正进入 `RUNNING` 的当前会话才清理标志并启动连通性观测，只有 `ERROR` 才记录“启动未完成”；源码门禁固定这组并发边界。
- `204c6ed`：VPN Extension 在系统 `VpnConnection.create()` 于取消清理之后才返回时，会重新登记该迟到连接并再执行一次幂等销毁，不再只留下无法释放的 TUN fd；同时补接清理循环判定与 `finally` 之间到达的重入请求，避免边界竞态漏掉最后一轮 TUN/核心/VPN 清扫。该路径只继续停止，不包含自动重连；源码门禁固定资源认领与边界补扫顺序。
- `e81d49b`：后台健康检查或可信网络规则自行拆除数据面后，若系统保留原 VPN Extension 实例，下一次用户明确连接会由 `onRequest` 暂存并只在旧 TUN/核心确认清理完成后启动，不再被当成重复请求忽略。每次会话使用独立代际，旧会话迟到的启动、健康探测、网络轮询和切网重载不能操作新会话；处于系统 `VpnConnection.create()` 等待时也不得宣布清理完成或叠加数据面。可信网络停止标志改为在创建新数据面前同步清除，避免运行后迟到清除本会话刚写入的自动断开证据。该恢复只响应新的用户启动，不构成后台自动重连。
- `4697013`：VPN 运行期诊断改为按一次性会话 ID 精确归因，并扫描当前会话最新的致命错误，不再让其后的清理 `info` 或已经写入的 inactive 状态把核心崩溃、切网恢复失败等异常伪装成普通断开；上一会话迟到错误也不能拆除新隧道。Extension 第一次状态心跳写入失败属于有界重试，改为信息级，只有连续达到失败阈值才发出会话级错误并清理，避免一次文件系统抖动被前台提前放大为断线。
- `bb1cc4b`：Xray 启动的动态端口选择、策略组展开、节点域名解析、运行配置构建与日志注入统一进入准备阶段错误收敛；异常不再把控制器永久留在 `STARTING`。错误原因先脱敏再进入 hilog/UI；若准备异常与用户停止并发，启动代际校验仍让停止结果优先。
- `ccc00fa`：sing-box 单节点兼容路径的核心日志准备与配置生成也进入同一错误收敛，不扩大预览功能范围，只保证异常不会残留“启动中”或绕过停止优先级。
- `f9016ef`：VPN Extension 的异步网络轮询改为串行，并在每个异步边界后复核停止闩锁，避免清理期间的迟到网络决策。
- `72f423b`：Hev TUN 桥接层按真实工作线程存活状态报告健康；Hev 提前退出后由既有连续采样触发清理，不再长期误报 TUN 正常。
- `8c5973d`：默认 gVisor tun2socks 停止时有限等待正常退出，再继续关闭核心与 VPN；异常超时后保留停止门闩，阻止同一扩展进程启动重叠的 TUN 数据面。
- `5943a80`：Hev TUN 停止也采用有限等待和同一门闩，避免异常工作线程把 VPN 清理永久卡住；原生桥同时拒绝在无适配器引擎时误调用 gVisor Stop。
- `264ca00`：随包 Xray 未导出可选配置预检符号时，本地代理日志如实显示“已跳过”；最终成功仍由实际核心启动和 SOCKS 入口探测判定。
- `f0e4f21`：应用设置写入失败不再返回假成功，读取时只在主键和备份都确实不存在时使用默认值；主设置损坏会恢复上一版，主备份都损坏则明确失败，不会把用户已选的本地代理模式静默重置为默认 TUN。首次保存同时建立恢复副本，恢复选择补充了 LocalUnit 用例。
- `06487c6`：VPN Extension 的跨进程状态写入返回真实成功结果；初始未连接状态或数据面 active 状态无法持久化时，使用主进程可识别的终止事件失败关闭并清理，不再宣告已启动。运行中单次心跳写入失败会立即重试，连续三次失败则清理而不自动重连；停止状态写入失败不阻塞 TUN/核心/VPN 销毁，并在销毁后再尝试一次，避免留下无人可接管的隧道。
- `f7b7ad3`：主进程的 VPN 启动握手不再只依赖共享诊断日志；日志终止事件仍优先，同时允许同一会话、开始时间不早于本次请求且 active/核心/TUN/心跳全部健康的持久状态确认启动。日志轮转或单次追加失败不会拆掉已真实就绪的隧道，旧会话、过期心跳和不完整数据面仍不能让界面进入“已连接”。
- `8b3803c`：停止握手区分“已写停止意图”和“资源确认清理完成”；只有 TUN 适配器、Xray、sing-box 与系统 VPN 都成功释放才写入同会话 `cleanupComplete` 并报告完成。诊断日志丢失时主进程可由该状态确认，任一资源失败则保留错误态与可重试的 VPN 句柄、将桌面卡片标为错误并尝试停止 Extension，不再无条件显示已断开；等待清理超时也会执行一次系统停止兜底。

### 节点导入与精简界面

- `b68c8f1`、`8e133a1`：相机/相册识别后展示预览，用户再次确认才保存，并对重复节点去重。
- `2c1f5ac`：扫码确认流程改用纯配置校验；重复、批量或无效内容不会在节点真正落库前改写当前 Profile，也不会把解析后仍无效的节点保存下来。
- `782e3eb`：外部深链与系统分享确认后的节点导入采用相同纯校验路径，只新增去重后的有效节点，不改写当前选择或运行配置。
- `d8afe3d`、`3f382bd`、`608107e`：扫码、深链与系统分享保持被动；订阅只保存来源、不自动请求，导入不偷偷切换运行中的节点。
- `cb152f9`、`1105f77`：相机权限仅在用户进入扫码动作时申请，所有扫码入口统一处理授权。
- `16bc058`：日常添加流程隐藏代理链与策略组创建入口，既有底层配置仍保持兼容。
- `d38a036`：日常添加流程进一步隐藏“新建完整 Xray JSON 配置”入口，只保留扫码/链接与单协议表单；已有完整配置、代理链和策略组仍可从节点详情查看或编辑。
- `ea381a6`：手动表单新增节点与兼容 JSON 新增路径先检查重复且只入库，不再切换当前节点或自动重连；编辑当前选中节点仍按原逻辑重连使修改生效。
- `a1b9966`、`6e3e04e`：扫码预览与公共订阅入口拒绝无主机、非法端口等畸形 URL；粘贴节点入口复用配置指纹去重。
- `632cbf6`：外部 URL Scheme、桌面快捷方式或控制卡片不能静默启动、停止或切换代理，需用户在 Hey 中再次确认；开机自动连接仍由独立设置控制。
- `3ed87a4`：扫码页离开时取消尚未执行的延迟相机任务，避免用户快速返回后仍弹出权限或相机界面。
- `0cbd6ad`：首页二维码按钮、导入页“扫码”和经确认的外部扫码动作携带一次性立即扫码参数，进入 Scanner 后直接申请权限并拉起系统扫码；普通页面导航仍遵循用户设置，不无故弹相机。
- `ad4627d`：扫码确认与手动链接二次确认的异步入库方法增加同步重入闩锁，不再只依赖下一帧才生效的按钮禁用，快速双击不能并发通过去重检查并重复写入。相机、相册和剪贴板取得的完整原文在扫码页离开时立即从页面实例清除，成功导入之外的取消/返回路径也不继续保留 UUID、密码或订阅 Token；源码门禁固定两个入口与页面销毁清理。
- `6112878`：节点与订阅的整档案“读取—修改—保存”统一进入进程级串行事务队列，避免扫码、系统分享、JSON/表单新增、订阅刷新、节点选择、删除和测速结果同时写入时各自基于旧档案覆盖其他更新。所有日常新增入口改用事务内去重并写入，两个并发入口不能再分别通过旧的重复检查后保存同一节点；单次事务失败不会使后续队列永久停摆。该队列只承诺同一应用进程内的存储事务顺序，不宣称跨进程锁。
- `39667bf`：排队写入使用的节点数组、测速结果、分组列表和备份恢复档案在 API 调用边界立即规范化复制，避免调用方在事务真正执行前继续修改原数组或对象，导致排队任务保存了调用时刻之外的数据。源码门禁固定所有整档案变更均先入同一队列，并固定可变批量参数的快照边界。
- `014d30f`：普通链接导入也改为纯校验、去重后入库；重复、无效和批量内容不再提前改写当前 Profile，成功导入不会切换或重启运行中的节点。
- `0e571b5`：单节点扫码预览除名称与协议外显示脱敏服务器地址和端口，便于确认目标节点，同时不展示 UUID、密码等凭据。
- `ff663a2`、`91387f6`：扫码与链接输入变化时清除上一轮失败提示，避免有效预览仍挂旧错误；补充相机扫码取消码回归用例，取消保持静默而权限/解码失败继续可见。
- `c7c31d0`：外部深链与系统分享确认框不再直接展示完整节点链接、UUID、密码或带 Token 的订阅 URL；单节点改为名称、协议和掩码端点摘要，批量内容显示数量，订阅只显示去掉用户信息、端口、路径与查询参数的来源主机。源码校验阻止原始外部 payload 再被插入首页弹窗，订阅主机提取补充了凭据、端口和 IPv6 用例。
- `df2badb`：相机、相册、剪贴板及系统分享的稳定输入在 ArkTS 解析失败时使用与最终导入一致的 libXray 兼容兜底生成安全预览；手动逐字输入不反复调用同步 N-API。native 转换失败信息在共享服务边界统一脱敏，避免底层回显完整节点链接或凭据。
- `7280e4b`：相机、相册和剪贴板得到的完整节点/订阅原文只在扫码页实例内暂存供用户确认导入，不再绑定到可截图的输入框；页面仅显示协议、数量或掩码端点等脱敏摘要，解析失败信息也在进入页面和运行日志前再次脱敏。手动键入仍保持可编辑，并新增源码守卫防止外部原文重新写回输入框。
