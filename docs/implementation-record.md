# Hey 精简客户端实施记录

> 开发分支：`codex/p0-vpn-mainline`；基线：`65bdea3`。本文件记录已落到源码的变更，
> 不把静态检查等同于真机验收。真机结果只填写在
> [`device-acceptance.md`](device-acceptance.md)。

## 已落地变更

### 代理与 VPN 主链

- `dcfb355`、`050a0d9`、`d97735f`、`fe7fbbe`：真实心跳、失败清理、扩展内异常清理与跨进程状态校正。
- `7c7b678`、`ef6bf64`：默认 DNS 经代理，并在可用系统版本上保护核心进程网络，降低 DNS 泄漏与自身 TUN 回环风险。
- `7f2fe6b`、`335184e`、`fccf1da`：停止闩锁及事务化 VPN 状态文件；崩溃恢复优先采用已完整关闭且结构有效的新临时状态，避免迟到启动或旧 `active` 备份造成误报。
- `89e7565`：VPN 状态临时文件在原子替换前执行 `fsync`；进程中断留下完整新状态时优先于旧主文件，半写临时文件仍安全回退，补充纯函数回归用例。
- `97c1602`、`995d940`、`47a3a33`：本地代理状态独立处理；启动前等待实际 SOCKS 入口，运行中连续探测数据面，失败清理但不自动重连。
- `cc9ec16`、`36c7d85`、`5d112c5`：TUN 与本地 SOCKS/HTTP 成为明确的可选模式；首页显示当前模式，VPN 网络自动化不再影响本地代理。
- `5322c9b`：解除 Hev TUN 引擎与用户可见本地 SOCKS/HTTP 的遗留强制联动；TUN 数据面只使用固定内部入口，本地代理监听继续由独立开关决定。
- `c7b527e`：清理“原生 TUN 入站”的旧说明，关于页明确展示可选的 TUN 与本地代理模式。
- `9d5505f`、`dc1f8a0`：观察底层 Wi-Fi/蜂窝变化但不强制重启 VPN；新连接跟随系统默认承载。
- `f9016ef`：VPN Extension 的异步网络轮询改为串行，并在每个异步边界后复核停止闩锁，避免清理期间的迟到网络决策。
- `72f423b`：Hev TUN 桥接层按真实工作线程存活状态报告健康；Hev 提前退出后由既有连续采样触发清理，不再长期误报 TUN 正常。
- `8c5973d`：默认 gVisor tun2socks 停止时有限等待正常退出，再继续关闭核心与 VPN；异常超时后保留停止门闩，阻止同一扩展进程启动重叠的 TUN 数据面。
- `5943a80`：Hev TUN 停止也采用有限等待和同一门闩，避免异常工作线程把 VPN 清理永久卡住；原生桥同时拒绝在无适配器引擎时误调用 gVisor Stop。
- `264ca00`：随包 Xray 未导出可选配置预检符号时，本地代理日志如实显示“已跳过”；最终成功仍由实际核心启动和 SOCKS 入口探测判定。
- `f0e4f21`：应用设置写入失败不再返回假成功，读取时只在主键和备份都确实不存在时使用默认值；主设置损坏会恢复上一版，主备份都损坏则明确失败，不会把用户已选的本地代理模式静默重置为默认 TUN。首次保存同时建立恢复副本，恢复选择补充了 LocalUnit 用例。

### 节点导入与精简界面

- `b68c8f1`、`8e133a1`：相机/相册识别后展示预览，用户再次确认才保存，并对重复节点去重。
- `2c1f5ac`：扫码确认流程改用纯配置校验；重复、批量或无效内容不会在节点真正落库前改写当前 Profile，也不会把解析后仍无效的节点保存下来。
- `782e3eb`：外部深链与系统分享确认后的节点导入采用相同纯校验路径，只新增去重后的有效节点，不改写当前选择或运行配置。
- `d8afe3d`、`3f382bd`、`608107e`：扫码、深链与系统分享保持被动；订阅只保存来源、不自动请求，导入不偷偷切换运行中的节点。
- `cb152f9`、`1105f77`：相机权限仅在用户进入扫码动作时申请，所有扫码入口统一处理授权。
- `16bc058`：日常添加流程隐藏代理链与策略组创建入口，既有底层配置仍保持兼容。
- `d38a036`：日常添加流程进一步隐藏“新建完整 Xray JSON 配置”入口，只保留扫码/链接与单协议表单；已有完整配置、代理链和策略组仍可从节点详情查看或编辑。
- `ea381a6`：手动表单新增节点与兼容 JSON 新增路径先检查重复且只入库，不再切换当前节点或自动重连；编辑当前选中节点仍按原逻辑重连使修改生效。
- `a1b9966`、`6e3e04e`：扫码预览与公共订阅入口拒绝无主机、非法端口等畸形 URL；粘贴节点入口复用配置指纹去重。
- `632cbf6`：外部 URL Scheme、桌面快捷方式或控制卡片不能静默启动、停止或切换代理，需用户在 Hey 中再次确认；开机自动连接仍由独立设置控制。
- `3ed87a4`：扫码页离开时取消尚未执行的延迟相机任务，避免用户快速返回后仍弹出权限或相机界面。
- `0cbd6ad`：首页二维码按钮、导入页“扫码”和经确认的外部扫码动作携带一次性立即扫码参数，进入 Scanner 后直接申请权限并拉起系统扫码；普通页面导航仍遵循用户设置，不无故弹相机。
- `014d30f`：普通链接导入也改为纯校验、去重后入库；重复、无效和批量内容不再提前改写当前 Profile，成功导入不会切换或重启运行中的节点。
- `0e571b5`：单节点扫码预览除名称与协议外显示脱敏服务器地址和端口，便于确认目标节点，同时不展示 UUID、密码等凭据。
- `ff663a2`、`91387f6`：扫码与链接输入变化时清除上一轮失败提示，避免有效预览仍挂旧错误；补充相机扫码取消码回归用例，取消保持静默而权限/解码失败继续可见。
- `c7c31d0`：外部深链与系统分享确认框不再直接展示完整节点链接、UUID、密码或带 Token 的订阅 URL；单节点改为名称、协议和掩码端点摘要，批量内容显示数量，订阅只显示去掉用户信息、端口、路径与查询参数的来源主机。源码校验阻止原始外部 payload 再被插入首页弹窗，订阅主机提取补充了凭据、端口和 IPv6 用例。

### Geo 数据

- `579f470`、`0a011b9`、`370f2b2`：内置默认发布源一次点击检查两个核心文件；默认与高级远程 `.dat` 都在大小、形态和 SHA-256 通过后才替换，本地导入也拒绝异常数据；失败保留旧文件与最后一次有效元数据。
- `d572f05`、`64be10c`：双文件事务、备份与进程中断恢复；冷启动先恢复 Geo 文件，再初始化 Xray 资源目录。
- `4c1f80c`：自定义资源名限制在沙箱数据目录内，并保留 `geoip`/`geosite` 核心名称，阻止覆盖或路径逃逸。
- `e9cea58`、`5e19463`：高级单文件与自定义 `.dat` 替换在 rename 前持久化临时数据；冷启动会恢复中断的 `.update.bak` 替换并丢弃未提交临时文件，避免 Xray 启动时缺失 Geo 文件；恢复决策已加入 LocalUnit 用例。
- `eb55f06`：代理运行中通过高级单文件、本地导入或删除改变核心 Geo 数据时，同样明确提示断开重连生效，不擅自热重启。
- `a679e96`：删除 Geo 文件时先清理单文件更新备份与临时文件；清理失败则保留正式文件和校验元数据，避免冷启动把用户已删除的旧备份恢复回来。
- 更新仍是手动触发；运行中不擅自重启代理，需用户重连后加载新数据。
- `c250791`：TUN 模式为 Xray 与 sing-box 增加固定仅回环的内部 HTTP 入口 `127.0.0.1:18083`；Hey 自身被排除在 TUN 外时，Geo 下载和出口验证仍可显式经过当前节点，不依赖用户开启可见 HTTP 代理，未连接时继续回退直连。
- `27339b1`：Geo 下载路由按当前会话的实际模式选择：明确空闲时直连，TUN 使用内部 `18083`，本地代理使用 `18081`；运行、启停或错误态下代理入口失败就报错并保留旧文件，不再让被排除于 TUN 的 Hey 静默降级直连泄漏更新请求。
- `c379246`：sing-box 的内部 HTTP 入站增加最高优先级代理规则，与 Xray 行为对齐；即使普通流量允许私网直连，Hey 自身经 `18083` 发出的 Geo/出口请求也不会因此绕过当前节点。
- `292c4da`：用户配置的 SOCKS/DNS 端口会避开应用固定 HTTP、VPN 数据面、内部 HTTP、测速和 metrics 端口，并消除 SOCKS 与 DNS 互占；动态 SOCKS 选端口同样过滤全部保留范围，避免启动时偶发监听冲突。
- `2b098cc`：VPN DNS 接受用户常见的方括号 IPv6 输入，但在写入 `VpnConfig.dnsAddresses` 前统一转换为裸 IP 并去重；同步修正设备测试中遗留的公共 DNS 默认值，默认仍使用当前 TUN 网段的虚拟路由地址。
- `fbff00a`：运行快照携带实际 TUN/本地代理模式；UI 进程重建后接管存活 VPN 时，不再把尚未作用于旧会话的新“本地代理”设置误当成运行事实，首页标签保持 TUN，出口复测继续使用内部 `18083`。
- `ec042ae`：VPN Extension 的跨进程状态只额外记录非敏感的 Profile 更新时间戳；UI 恢复时若当前选中节点版本与后台隧道不一致，不再拿新节点替旧隧道测速或归属出口，并明确要求用户手动断开重连。旧状态文件无该字段时保持兼容。
- `28cc09d`、`fcfc0cd`：可信网络自动断开标志按时间戳归属于具体 VPN 会话；新 Extension 会话主动清旧标志，恢复和前台网络观察入口都只接受晚于当前会话启动的停止时间，避免上次自动断开的残留文件压制或错误归零健康新 VPN。
- `f038ffa`：Geo 文件结果与元数据落盘结果分开呈现；即使校验记录保存失败，也保留“已更新/已最新”的真实结论，并在代理运行中继续明确提示断开重连。
- `49ee44a`：双文件事务的提交标记不再仅按“文件存在”判断，必须完整写入固定字节才算提交；进程若在创建标记后、写入或 `fsync` 前终止，冷启动会按未提交事务回滚，不保留半套 Geo 文件。
- `4483709`：内置双文件检查、高级/自定义下载、本地导入和删除统一使用进程内资源变更互斥；即使更新中离开并重进页面、局部 UI 忙碌状态丢失，也不能让另一个 `.dat` 操作插入事务窗口。
- `9975ecd`：自定义 `.dat` 来源列表和 Geo 版本/哈希记录分别保留上一份有效数据，首次保存即建立副本；主记录损坏时回退，主备份都损坏则明确失败，写入错误不再被当作保存成功。资源页遇到读取失败会退出加载态并显示脱敏错误，自定义来源保存失败也不会先污染页面内存列表；恢复选择补充了 LocalUnit 用例。

### 可观测性与交付

- `ab64729`、`8a59556`：连接页显示经当前代理验证的出口 IP，并区分“数据面运行”与“外网已验证”。
- `6151023`：返回首页、点按出口胶囊或已启用网络场景监听时发生承载变化，都会经当前代理复测出口；复测失败清除旧 IP，不重连、不改变 TUN/本地代理选择。
- `0f5de28`：网络变化观测与可信网络自动断开解耦；自动化关闭时仍在 UIAbility 生命周期内观察承载并复测出口，但绝不连断。评估期间到达的新事件和启停忙碌期事件会合并补判，不再静默丢失。
- `2c1dd3b`：UIAbility 网络监听增加生命周期代际校验；旧 Ability 在途的设置读取、网络探测或停止标志检查恢复后立即作废，不能在监听销毁/重建后迟到断开新会话或复测错误出口。
- `3b6831e`：控制卡片持久状态区分 VPN/TUN 与本地代理；系统单独刷新卡片时重新核对 VPN Extension 跨进程心跳，停止、过期或数据面不完整时不再沿用旧“运行中”。
- `c02da1e`：系统单独刷新控制卡片时也会探测本地代理固定回环 HTTP 入口 `18081`；UI 进程被回收、核心退出或旧状态残留后，卡片会纠正为错误而不继续显示“运行中”。该探针只证明本地监听器存活，不冒充外网或 VPS 可用性。
- `0bd813d`：主界面显示 VPN/TUN 运行时若连续三次都读不到任何有效 Extension 状态文件，会清理残留并进入错误态，不再无限保留假“已连接”；单次临时读取/替换失败会被容忍，本地代理不受此规则影响，且异常后不会自动重连。
- `e6d1dba`：锁屏或后台恢复后若 Extension 的 active 心跳只是过期/单次报告数据面不完整，主界面先等待 12 秒让后台定时器恢复或由 Extension 完成双采样判定；健康心跳恢复即继续接管，持续异常才清理。单条 `vpn-stats=false` 不再抢先拆隧道，本会话明确的 VPN 错误仍立即清理，且全程不自动重连。
- `f413485`：诊断错误只允许本次 VPN 会话中由 VPN Extension 写入的记录改变连接状态；后台订阅失败、旧会话错误和本地代理无关日志仍会展示，但不能把健康连接误标为错误。本地代理继续由实际 SOCKS 探测判定。
- `5cb9111`：运行中的本会话 VPN Extension 致命错误不再只改 UI；先幂等停止底层控制器并清理残留，再保留具体错误等待用户手动重连。启动阶段仍由原启动协程独占失败回滚，避免刷新定时器与启动流程并发停止。
- `83413d7`：共享运行控制器在任何异步边界前同步发布 `STARTING/STOPPING`，并直接拒绝重叠启停；可信网络监听、首页和日志页不再能在同一次核心/TUN 清理窗口内并发启动或重复停止。底层控制器也拒绝从 `STOPPING` 直接启动。
- `0bfcaef`：每次 VPN 启动生成一次性会话 ID，并贯穿启动 Want、跨进程状态、启动/失败/清理事件和停止命令；主进程只接受目标会话的完成事件，Extension 忽略指向旧会话的迟到停止命令。UI 进程重建接管时同时恢复该 ID，避免旧日志或旧控制请求确认/拆除新隧道。
- `5dc4807`：VPN 与本地代理的数据面异常清理同样在等待底层停止前同步进入 `STOPPING`；首页、日志页与网络监听即使同时刷新，也不能重复执行故障清理。
- `8973b7f`：首页初始化与 `onPageShow` 不再并发消费动作或定时刷新；先读取流量基线并接管/校正后台真实运行态，再处理开机启动、设置重启、分享和外部控制。UI 进程重建不会对仍健康的 Extension 重复启动，也不会根据后台断开前的旧状态误重连。
- `3d66c59`：设置页只在模式、DNS、路由、监听端口、TUN/核心配置等真实数据面字段变化时请求重启；主题、语言、列表布局、扫码/删除偏好、首页观测和可信网络自动化可即时生效，不再无故拆掉健康连接。
- `b358871`：前台监听与 VPN Extension 后台观察的网络去重签名加入非持久 NetHandle 标识；即使没有定位权限或 Wi-Fi 隐藏 SSID，同类型承载切换也能被识别并触发出口失效/复测，而可信网络判断仍只使用用户配置的 SSID/蜂窝选项。
- `a765aa9`、`e3e6046`、`34e8f98`：VPN Extension 清理时并行撤销速度常驻通知并主动重置桌面控制卡片；两项 UI 清理各自有 2 秒上限，且仍受同一清理闩锁保护，失败或重入不会阻塞/重叠 TUN、核心与系统 VPN 的释放。
- `e00eebf`、`f136d82`、`7d8bfea`：诊断脱敏、测速错误净化及 UI 进程恢复后的日志接管。
- `9989256`、`b65ff19`、`2729d73`：诊断文件、应用/核心日志、相关 ArkTS hilog 与扫码错误路径统一隐藏完整订阅/节点 URL、UUID、密码、Token、IP 与节点主机端点，同时保留错误类型和 HTTP 状态等排障信息。
- `01bd3aa`：Geo 检查与高级自定义下载的系统网络错误在进入可复制日志或提示前统一脱敏，避免带查询凭据的下载源泄露。
- `d321cb4`：原生桥不再把核心/探测失败的完整文本直接写入公开 hilog；原始错误仍返回 ArkTS，经统一脱敏后用于界面和诊断。
- `2c859e8`：链接/深链导入、订阅扫码、Geo 文件选择与扫码、启停/测速及首页辅助任务的异常在进入页面提示或应用日志前统一脱敏；底层若回传完整分享链接、订阅 URL、节点端点或凭据，也不会出现在截图和内存日志中。
